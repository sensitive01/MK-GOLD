1. EXECUTIVE SUMMARY
================================================================================
Currently, mkgold.in (customer website on Vercel) and MK-GOLD CRM (internal ERP
on Node/Express + MongoDB) run on separate servers with separate databases.

When customers submit lead forms on mkgold.in, the website stores them in its own
SQL database (returning integer IDs like id: 711). The leads DO NOT automatically 
reach the CRM in real time. Instead, the marketing team periodically exports 
CSVs and manually imports them into the CRM.

GOAL:
Build an automated real-time Webhook Bridge between mkgold.in and MK-GOLD CRM so 
every lead submitted on the website (Calculator, Popup, or Meta Ad) is instantly 
received by the CRM, automatically assigned to an active telecaller via round-robin, 
and displayed on the telecaller's screen within 1-2 seconds.

--------------------------------------------------------------------------------
API 1 — CALCULATOR LEAD FORM
--------------------------------------------------------------------------------
Endpoint: POST https://mkgold.in/api/v1/leads
Trigger: Gated modal on mkgold.in/sell-gold. Visitor must fill in details to unlock
         the MCX gold calculation widget.
Headers: Content-Type: application/json
Payload:
{
  "name": "Prajwal Kumar",
  "phone": "9345004690",
  "city": "Bangalore",
  "gold_type": "jewellery",
  "weight_grams": 20,
  "purity_karat": 22,
  "source": "calculator-gate"
}
Validation:
- name and phone are strictly mandatory (400: {"error": "name and phone are required"})
- phone must be 10 digits starting with 6, 7, 8, or 9 (/^[6-9]\d{9}$/)
Result on Submit: Returns 201 Created ({"success": true, "id": 711}) and unlocks
the rate calculator on the user's screen.

API 3 — META (FACEBOOK & INSTAGRAM) LEAD ADS WEBHOOK
--------------------------------------------------------------------------------
Endpoint: https://mkgold.in/api/v1/meta-leads
Trigger: When a mobile user submits an Instant Form on a Facebook or Instagram ad.
Two Sub-Handlers:
1. GET Request (Meta Verification Handshake):
   - Meta calls GET with hub.mode, hub.challenge, hub.verify_token.
   - CURRENT ISSUE: Returns "500 Server misconfigured" because META_VERIFY_TOKEN
     environment variable is missing in Vercel.
2. POST Request (Lead Event Ingestion):
   - Meta delivers a webhook payload with object: "page" and leadgen_id.
   - Server responds 200 OK ({"status": "ok"}), then uses the leadgen_id to 
     fetch the user's details via Meta Graph API.

Endpoint: GET https://mkgold.in/api/v1/calculate?weight=10&purity=22

4. TELECALLER ROUND-ROBIN AUTO-ASSIGNMENT MECHANISM
================================================================================
In the CRM backend (backend/services/lead.js), whenever a lead is created without
a pre-assigned user:

  let currentTelecallerIndex = 0;
  if (!data.assignedTo) {
    const User = require("../models/user");
    const telecallers = await User.find({ 
      userType: "telecalling", 
      status: "active" 
    }).select("_id").lean();

    if (telecallers.length > 0) {
      data.assignedTo = telecallers[currentTelecallerIndex % telecallers.length]._id;
      currentTelecallerIndex = (currentTelecallerIndex + 1) % telecallers.length;
    }
  }

How Telecallers See It:
- Telecallers log into their CRM dashboard.
- The query specifically displays leads where:
  assignedTo == user._id (or unclaimed leads).
- Thus, the moment a lead is inserted with assignedTo, it shows up exclusively 
  in that telecaller's calling queue.

5. KEY TECHNICAL CONCEPTS EXPLAINED
================================================================================

WHAT IS A WEBHOOK?
Think of a Webhook as an automated doorbell:
- Without a webhook (Manual): You have to keep checking the door every 10 minutes 
  to see if a package arrived. (Marketing manually downloading CSVs).
- With a webhook (Instant): The delivery person rings your doorbell the exact 
  second the package is dropped off. (The website pushes the lead to the CRM 
  the millisecond the customer hits "Submit").

WHAT IS AN x-api-key & HOW TO GENERATE IT?
An x-api-key is a shared secret password in the HTTP header:
- Since the CRM webhook URL is public on the internet, anyone could post spam.
- With x-api-key, the CRM checks if the request contains the secret key. If yes, 
  it accepts the lead; if no, it rejects with 401 Unauthorized.

Generate an x-api-key in terminal:
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
Example key:
  mkgold_sec_e4b1a859f72c019958dcbe2da831ec5e921d782103f6f34e62a8435d21c43b91

========================================================================PART A: MK-GOLD CRM BACKEND (DEDICATED WEBHOOK ROUTER & CONTROLLERS)
---------------------------------------------------------------------
1. Dedicated Webhook Router: backend/routes/webhook.js
   - Mounted in backend/app.js at /api/v1.0/webhook
   - Route 1: POST /api/v1.0/webhook/leads (Calculator & Popup website forms)
     * Protected by verifyWebhookKey middleware (checking x-api-key header)
   - Route 2: GET  /api/v1.0/webhook/meta (Meta Verification Handshake)
     * Validates hub.mode === 'subscribe' && hub.verify_token === process.env.META_VERIFY_TOKEN
     * Echoes hub.challenge with 200 OK
   - Route 3: POST /api/v1.0/webhook/meta (Meta Live Lead Events)
     * Responds immediately 200 { status: "EVENT_RECEIVED" }
     * Ingests both direct forwarded leads (from website/Zapier) and raw Meta Graph API events
   - Route 4: GET  /api/v1.0/webhook/health (Service health check)

2. Dedicated Controllers:
   - backend/controllers/webhook/lead.js:
     * Handles web leads (calculator gate & popup)
     * Performs field normalization (phone -> mobile, weight_grams -> weight, remarks formatting)
     * Performs same-day deduplication (appends repeat enquiry disposition)
     * Automatically assigns to telecaller using Option B (Fair Load Balancing)
   - backend/controllers/webhook/meta.js:
     * Handles Meta verification handshake and event processing
     * Automatically extracts name, phone, city, campaign, ad, and form details
     * Assigns lead to active telecaller using Option B

3. Option B Telecaller Balancing (backend/services/lead.js):
   - Queries MongoDB for leads assigned today across active telecallers.
   - Dynamically selects the telecaller with the lowest lead count today.
   - Fully persistent across server restarts and concurrent requests.
